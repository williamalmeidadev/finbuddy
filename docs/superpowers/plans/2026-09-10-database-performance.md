# FinBuddy Database & Performance Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Perform an audit and targeted database performance optimization pass over the FinBuddy backend REST API. Improve query efficiency, eliminate N+1 spending aggregations, add composite database indexes, and enforce atomic balance update concurrency guards without altering financial semantics or adding unnecessary infrastructure.

**Architecture:** Add targeted composite indexes in `prisma/schema.prisma` for high-frequency time-series and filtered lookups (`Transaction`, `RecurringTransaction`, `Budget`, `Transfer`). Refactor `BudgetRepository` and `FinancialSummaryRepository` to aggregate spending via single-pass `groupBy` queries. Harden `TransferRepository` with atomic row-level balance predicates (`balance >= amount`) to prevent concurrency race conditions.

**Tech Stack:** NestJS 11, Prisma 7, PostgreSQL 17, TypeScript, Jest, Supertest.
