# FinBuddy — AI Agent Observability & Auditability Documentation (Phase 14)

## 1. Executive Summary & Architecture

Phase 14 introduces comprehensive observability, structured logging, request correlation, bounded metrics, and database auditability for the FinBuddy AI Agent (`src/ai-agent/`).

Every AI interaction is traceable end-to-end via unique correlation identifiers without compromising data privacy or exposing sensitive financial values and secrets.

```text
HTTP Request (X-Request-Id)
  │
  ▼
AiAgentController
  │  (requestId, aiRequestId)
  ▼
AiAgentService / AiAgentOrchestratorService
  │
  ├──► Structured Logging (JSON) with Redaction
  ├──► Bounded MetricsService Counters
  └──► Database Audit Log (AiAuditEvent for Financial Mutations & Confirmations)
```

---

## 2. Request Correlation Model

1. **`requestId`**:
   - HTTP request correlation ID extracted from the incoming `X-Request-Id` header (or generated by `RequestIdMiddleware`).
   - Correlates the entire HTTP transaction lifecycle across middleware, controller, services, and database audit events.

2. **`aiRequestId`**:
   - Unique identifier (`ai-req-<uuid>`) generated at the start of an AI multi-turn execution run.
   - Correlates all LLM calls, tool execution steps, argument validation attempts, and confirmation proposals within a single user message processing run.

3. **`confirmationId`**:
   - UUID identifying a pending or executed financial write action (`create_transaction`).
   - Connects the initial AI proposal event with subsequent confirmation, execution, expiration, or cancellation events.

## 3. Event Taxonomy & Error Codes

### Standard Event Names (`AiEventName`)

- **Request Lifecycle**:
  - `ai.request.started`: Initiated user request processing.
  - `ai.request.completed`: Successfully finished message processing run.
  - `ai.request.failed`: Processing failed due to timeout, provider error, or iteration bounds.

- **LLM Provider Calls**:
  - `ai.llm.started`: Request dispatched to OpenAI Responses API.
  - `ai.llm.completed`: OpenAI Responses API returned completion output.
  - `ai.llm.failed`: OpenAI Responses API call errored.

- **Tool Calling & Execution**:
  - `ai.tool.requested`: Model requested function tool invocation.
  - `ai.tool.started`: Application tool execution initiated.
  - `ai.tool.completed`: Application tool executed successfully.
  - `ai.tool.failed`: Application tool execution threw an exception or returned failure.
  - `ai.tool.validation_failed`: Tool argument schema validation failed.
  - `ai.tool.authorization_denied`: Tool capability authorization denied by security policy.

- **Confirmation Flow**:
  - `ai.confirmation.created`: Financial write proposal created and awaiting user confirmation.
  - `ai.confirmation.confirmed`: User confirmed and executed pending financial write action.
  - `ai.confirmation.cancelled`: User cancelled pending confirmation request.
  - `ai.confirmation.expired`: Confirmation request exceeded TTL and was rejected.
  - `ai.confirmation.rejected`: Confirmation execution attempt failed validation, authorization, or replay check.

- **Memory Lifecycle**:
  - `ai.memory.created`: Structured memory entry created.
  - `ai.memory.updated`: Structured memory value updated.
  - `ai.memory.deleted`: Single or bulk user memory deleted.
  - `ai.memory.rejected`: Memory save rejected by key allowlist, length, format, or prompt injection policy.
  - `ai.memory.loaded`: User memories retrieved for model context injection.

### Error Taxonomy (`AiErrorCode`)

- `INVALID_ARGUMENTS`: Argument schema validation failure.
- `AUTHORIZATION_ERROR`: IDOR or capability authorization denied.
- `TOOL_NOT_FOUND`: Tool requested by model is not in registry.
- `TOOL_EXECUTION_ERROR`: Financial service execution thrown error.
- `CONFIRMATION_EXPIRED`: Confirmation request exceeded TTL.
- `CONFIRMATION_ALREADY_CONSUMED`: Single-use replay attempt rejected.
- `CONFIRMATION_CANCELLED`: Attempted to execute cancelled confirmation.
- `LLM_ERROR`: OpenAI API provider error or timeout.
- `TIMEOUT`: Exceeded maximum allowed tool iteration steps.
- `INTERNAL_ERROR`: Unexpected internal error.

## 4. Privacy & Secret Redaction Engine

`AiAgentObservabilityService.sanitizeMetadata()` enforces zero-leakage privacy rules:

### Blacklisted Key Patterns
Keys matching the following regex patterns are masked with `"[REDACTED]"`:
- `api_key`, `token`, `password`, `secret`, `authorization`, `cookie`, `bearer`
- `credit_card`, `ssn`, `database_url`
- Financial payload values: `amount`, `description`, `balance`

### Sensitive Value Patterns
String values containing secrets are sanitized via regex replacement:
- `sk-[a-zA-Z0-9_-]+` -> `"[REDACTED]"`
- `Bearer [a-zA-Z0-9._-]+` -> `"[REDACTED]"`
- `postgres://...` -> `"[REDACTED]"`

### Raw Storage Restrictions
- **Zero Raw Prompts**: User prompts and raw LLM completion texts are NEVER saved in database audit tables.
- **Zero Financial Payload Values**: Financial transaction amounts and descriptions are redacted from database audit metadata.

## 6. Database Audit Model (`AiAuditEvent`)

Financial audit events are persisted in PostgreSQL via Prisma model `AiAuditEvent`:

```prisma
model AiAuditEvent {
  id             String   @id @default(uuid())
  userId         String   @map("user_id")
  requestId      String?  @map("request_id")
  aiRequestId    String?  @map("ai_request_id")
  eventType      String   @map("event_type")
  toolName       String?  @map("tool_name")
  confirmationId String?  @map("confirmation_id")
  status         String
  riskLevel      String?  @map("risk_level")
  metadata       Json?
  createdAt      DateTime @default(now()) @map("created_at")

  user User @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
  @@index([eventType])
  @@index([requestId])
  @@index([aiRequestId])
  @@index([confirmationId])
  @@map("ai_audit_events")
}
```

### Append-Only Integrity
- `AiAuditEvent` is strictly append-only.
- No HTTP `GET`, `PATCH`, or `DELETE` endpoints expose or mutate audit logs to public API users.

## 5. Token Accounting & Cost Estimation Metrics (Phase 23)

In addition to runtime observability, FinBuddy tracks token usage breakdown and estimated USD cost for model invocations:

- **Token Metrics**: `inputTokens`, `outputTokens`, `totalTokens`, `cachedTokens`, `reasoningTokens` parsed from OpenAI Responses API.
- **Cost Metrics**: Calculated dynamically via `MODEL_PRICING_TABLE` (`gpt-4o`, `gpt-4o-mini`, `gpt-5.5`).
- **Evaluation Reports**: Evaluator outputs structured JSON summaries containing latency percentiles (p50/p95), category pass rates, total tokens consumed, and cost deltas across repeated runs.
